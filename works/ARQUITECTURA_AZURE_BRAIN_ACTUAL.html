1. Principio de diseño

Regla de oro: Azure (y heurísticas) clasifican la intención del cliente. Los números, fechas y productos solo salen del snapshot Core o de la base de conocimiento. La matriz VF01 / funcional juzga si la respuesta es correcta.

No se improvisan cuotas, ni se usa la mora como cuota, ni se responde DAP ante “¿estás ahí?”. La prosa natural (Fase 2) solo reescribe hechos ya verificados.

3. Pipeline de un turno (POST /turn)

  1. Sesión + snapshot — Resuelve customer_id / conversation_id, carga o reutiliza el portafolio Core.
  2. Azure Brain (si flag ON) — Clasifica intención → ejecuta grounded → FAQ/Foundry si es conocimiento → redacción natural. Sale temprano si hay texto.
  3. Fastpath histórico — Guardrails deterministas (saludos, campos, FAQ, reclamaciones…) si el brain no aplicó o hizo fallthrough.
  4. LLM + ensamblaje — Agent Framework + verificador semántico para casos no resueltos.
  5. Knowledge post-LLM — Foundry → Azure Search → FAQ/institucional si la intención es de conocimiento.
  6. Canal — client_response / app_channel + auditoría.

Si el usuario está eligiendo una opción de producto (“la que termina en 7615”), el brain cede al path de selección para no romper el pending de clarificación.

4. Capa Brain — cada componente

Paquete src/genesis_cognitive/brain/. Es el camino preferido en QA :8447.

Orquestación

turn_orchestrator

Coordina un turno brain: clasifica → grounded → si route=knowledge resuelve FAQ→Foundry → aplica redacción natural. Devuelve None para fallthrough al fastpath.

brain/turn_orchestrator.py
Clasificación

azure_intent_brain

Cerebro de intención. Llama Azure OpenAI con JSON schema estricto (IntentPacket). Si falla o el flag está off, usa heurística local. Overrides de seguridad: cuánto≠cuándo, débito≠crédito, upcoming≠DAP, y chitchat gana a producto.

brain/azure_intent_brain.py
Conversación

social_intent

Detecta presencia (“¿estás ahí?”), correcciones (“no te pregunté por depósitos”), gracias, acuses y small-talk. Prioridad alta: evita que Azure/FAQ inventen un producto.

brain/social_intent.py
Contratos

intent_types

Define IntentPacket (family, product, field, scope, confidence…) y GroundedResult (texto, status, route, trace). Familias: personal, knowledge, process, ood, greeting, chitchat, clarify.

brain/intent_types.py
Semántica Core

core_facts_catalog

Catálogo oficial API Productos → campos del snapshot. Marca qué existe (disponible TC, mora≠cuota) y qué no (monto de cuota contractual ausente en portafolio).

brain/core_facts_catalog.py
Hechos personales

grounded_executor

Única boca de hechos personales: lee solo el snapshot. Maneja multi-tarjeta, débito, préstamos, DAP, pagos próximos, chitchat y saludos. Si es knowledge, deja route=knowledge vacío de texto para que el orquestador llame FAQ/Foundry.

brain/grounded_executor.py
Prosa

natural_draft

Fase 2: Azure reescribe el texto de hechos en español natural. Validación anti-alucinación: no puede introducir montos/fechas nuevos. Si falla o inventa, se conserva el texto grounded original.

brain/natural_draft.py
Entrada HTTP

contract_inspector_app

Hook del brain antes del fastpath. Persiste sesión, limpia sticky de producto en correcciones chitchat, arma la respuesta JSON del canal.

demo/contract_inspector_app.py

5. Boca de hechos — Core, FAQ, Foundry, Search

Core

CustomerContextSnapshot

Portafolio inmutable del cliente autenticado: cuentas, TC, préstamos, DAP, máscaras, tasas, fechas. Se carga con context_info, lab login o mapeo Core. Nunca lo inventa el LLM.

context/customer_context_snapshot.py
FAQ

FAQ lexical VF01

Match de frases institucionales / procesos con score. Overlay Fase 1 para fixes. Si el score es alto y no hay preferencia Foundry, responde directo.

router/faq_guardrail.py · data/kb_faq_*.json
Foundry

Foundry KB Agent

Agente genesis-kb-agent-poc en Azure AI Foundry. Solo conocimiento de negocio (nunca saldos personales). Usa el índice Search del proyecto.

rag/foundry_kb_agent.py
Search

Azure AI Search

Índice vectorial (p. ej. bsc-kb-conocimiento). Fallback RAG si Foundry no responde o en el path LLM histórico.

rag/local_rag.py · scripts/index_kb_azure.py

6. Fastpath histórico y LLM (red de seguridad)

Siguen activos cuando el brain está off, falla, o hace FALLTHROUGH. No se eliminaron: son la red de seguridad y cubren edge cases aún no migrados.

ComponenteRolArchivo
Fastpath Guardrails deterministas: saldos, DAP, reclamación, FAQ, upcoming payments… router/field_guardrails.py
Product focus / sticky Memoria de producto en sesión; se limpia en corrección chitchat router/product_focus.py
Agent Framework Proposer + verifier LLM para contratos complejos pipeline en contract_inspector_app
