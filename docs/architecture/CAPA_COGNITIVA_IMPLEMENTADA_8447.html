4. P0 — Puerta de confianza (fiabilidad)

Función central: prefer_foundry_for_faq_hit() en knowledge_followup.py. Evita que un FAQ “genérico” cierre el turno cuando el usuario pide detalle (requisitos, cargos, solicitud, consumo, robo, etc.).

5. P1 — Cache Foundry (ahorro sin perder fiabilidad)

Módulo foundry_kb_cache.py. Clave = hash(topic|pregunta_normalizada). Solo cachea FOUNDRY_KB_ANSWERED. No cachea personal, clarify ni respuestas basura.

6. Contexto multi-turno y comparaciones

  • last_knowledge_topic mantiene el producto del hilo (Crédito Diferido, Multicrédito vs Cuotas, crédito/débito…).
  • expand_knowledge_question convierte follow-ups cortos (“¿cómo lo solicito?”, “me refería a la primera”) en pregunta explícita.
  • Comparaciones KB (Multicrédito/Cuotas, crédito/débito) tienen camino dedicado para no caer a portafolio personal ni a OOD.
  • No se guarda KB_AMBIGUITY como topic (evita envenenar el hilo).

No se reentrena un LLM con datos del cliente. El aprendizaje operativo es cobertura de expresiones → más hits FAQ baratos y estables; Foundry queda para lo nuevo o detallado.

10. Cómo probar (rápido)

  1. Abrir /pruebas o usar webhook con ClientId: CUST001.
  2. Conocimiento multi-turno: “¿Qué es Crédito Diferido?” → “¿requisitos?” → “¿cómo lo solicito?”.
  3. Comparación: “Compárame Multicrédito y Cuotas BSC” / “crédito vs débito”.
  4. Personal (snapshot): “¿cuál es mi saldo?” — no debe invocar Foundry.
  5. Repetir una pregunta Foundry dos veces: la 2ª puede marcar FOUNDRY_KB_CACHE_HIT.
